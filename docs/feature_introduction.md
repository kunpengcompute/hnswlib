# 特性介绍

## 项目概述

hnswlib优化版是基于开源hnswlib项目，针对ARM架构平台进行深度优化的高性能向量搜索库。该版本保持了与原始hnswlib API的完全兼容性，同时在ARM处理器上实现性能提升。

## 算法原理<a name="section975104591010"></a>

hnswlib的核心原理是基于分层可导航小世界（HNSW）图结构来组织高维空间中的数据点，从而在近似最近邻搜索中实现查询速度与精度之间的高效平衡。

-   该算法通过构建一个多层图结构来工作，其中底层图包含数据集中所有节点，而越高层数则包含越少的节点，这些高层节点间形成的“长连接”充当了快速导航的“高速公路”。
-   当需要插入一个新节点时，算法会通过一个指数衰减的概率分布随机决定该节点出现的最高层数，然后从该层开始向下，逐层寻找该节点的最近邻并建立连接。
-   关键参数M控制了每个节点在各层中的最大连接数，直接影响图的稠密度和搜索质量。在进行最近邻搜索时，查询过程从最高层入口点开始，利用长连接快速定位到目标区域，然后逐层向下细化搜索，通过贪婪遍历逼近最近邻节点。
-   参数ef则用于动态控制搜索过程中维护的候选队列大小，其值越大通常搜索精度越高但耗时越长。这种分层结构有效减少了搜索时需要访问的节点数量，使得hnswlib在面对大规模高维数据时，相比传统精确搜索方法能显著提升效率，同时保持较高的召回率。

FP16数据类型将每个向量分量的存储空间从FP32的4字节减少到2字节。这使得在构建HNSW索引时，所需的内存空间大幅降低，从而允许在有限的硬件资源下处理更大规模的向量数据集。同时，针对鲲鹏ARM架构，对hnswlib的距离计算算法进行优化，提升了图检索过程中的节点距离比较效率。

## 核心优化特性

### 1. FP32距离计算的NEON指令优化

**功能说明**：利用ARM NEON SIMD指令集加速FP32向量的L2距离和内积距离计算，根据向量维度自动选择最优计算路径，显著提升距离计算速度。

#### 技术实现
- **SIMD向量加速**：使用ARM NEON 128位向量寄存器，一次处理4个或16个单精度浮点数
- **多版本实现**：
  - `SIMD16`：当向量维度是16的倍数时，使用16元素处理路径
  - `SIMD4`：当向量维度是4的倍数时，使用4元素处理路径
  - `Residuals`：当向量维度不是上述倍数时，使用主路径+残差处理的混合方法
- **指令级并行**：充分利用NEON指令的并行执行能力，减少循环次数

#### 支持的距离类型
- **L2距离**：`L2SqrSIMD16ExtNEON`、`L2SqrSIMD4ExtNEON`等
- **内积距离**：`InnerProductSIMD16ExtNEON`、`InnerProductSIMD4ExtNEON`等


### 2. FP16数据类型支持

**功能说明**：新增FP16半精度浮点数支持，在保证搜索质量的前提下，减少内存占用并进一步提升计算性能。

#### 技术实现
- **半精度浮点数支持**：新增`float16_t`数据类型支持，内存占用对比FP32显著下降
- **NEON FP16指令**：使用ARM NEON的FP16专用指令集进行加速
- **自动类型转换**：在距离计算过程中高效处理FP16到FP32的转换
- **完整的空间实现**：
  - `L2SpacePh`：FP16 L2距离空间
  - `IPSpacePh`：FP16内积距离空间

#### 核心优势
- **内存节省**：向量数据内存占用减少
- **性能提升**：FP16版本的性能对比FP32NEON优化版本有进一步提升


### 3. 底库ID重排优化

**功能说明**：使用优化版本的hnswlib并开启`USE_NEON`宏后，自动开启AggressiveRenumberInplace，重排优化HNSW图的节点ID，在保持图拓扑结构不变的前提下，最大化邻居节点ID的局部连续性，可以提高缓存利用率和访问速度。

#### 技术实现
- **内存重排**：重新排列索引元素，提高内存访问局部性
- **BFS遍历**：使用广度优先搜索遍历图结构，确保相邻节点在内存中也相邻
- **删除元素管理**：将删除的元素移动到内存末尾，保持有效元素的紧凑排列
- **多线程支持**：使用OpenMP并行处理内存复制和链接列表更新

### 4. 预取优化

**功能说明**：在hnswlib搜索层次化图的算法中，使用预取方法，将用于记录节点访问状态的数组和用于根据节点的内部ID获取该节点的数据指针加载到缓存中，以减少后续访问的延迟。

#### 技术实现
- **数据预取**：在访问数据前提前将其加载到缓存中
- **链接预取**：预取下一个要访问的节点链接
